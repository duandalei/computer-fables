按牌分银

—— 一个关于“一条街上，谁该听谁”的故事

青溪县的三月庙会，是方圆百里最热闹的市面。长街从码头一直铺到城隍庙，三百多个摊子，一摊挨着一摊；卖药材的、卖绸缎的、卖瓷器的、卖南货的，谁都能在这条街上找到。

沈家是县里最大的南货行，一年四季的货都在这条街上办。早年间，沈家只有一个采买——一位姓周的老总管。

老总管跑了二十年庙会，街上的掌柜没有他不认得的。可认得归认得：绸缎庄的胡掌柜每年给他留两匹缎子，他便年年只进胡家的货；城南的窑器明明胎厚釉匀，他嫌路远，走到半街就折回来了；有些摊子今年新出的东西，他连看都没看过。一年下来，账上没少花钱，货却总差着一截。

沈家少爷跟着跑了两回，看出了病根：不是老总管眼力不好，是一个人的眼睛，看不过来一条三百号的长街；也不是他存心偏私，是一个人心里那张“该买什么”的单子，常常敌不过酒桌上的交情。

那年开春，少爷立了新规矩。

第一件：每个摊子门前挂一块招子，只写“我这里应的是什么”——药材写药材，绸缎写绸缎，几时到货、什么成色，都写在牌上；不写掌柜姓什么，也不写跟谁有交情。

第二件：每个采买手里一张单子，写明“我缺的是什么”。单子上不写“我要胡家的缎子”，只写“我要一匹不掉色的素缎”。

第三件，也是最要紧的一件：采买不必再一家一家地问。只把单子上的话，与沿街每一块招子上的话对一遍；对得上的，多分银子；对不上的，少分或不分。一天的银子总数是定死的，按对得上的程度分完为止。银子分定了，才照份额取货——取来的各家货色，按份额合成一包。

新规矩头一天，老总管站在街口看了半晌，摇头：“不认得人，怎么买货？”

少爷说：“正因不认得人，才这么买。”

招子是明写的，人人都看得见；单子也只论货，不论人。胡掌柜再塞缎子也没用——银子不看他，只看招子上的话对不对得上单子。城西窑器铺的招子上写着“胎厚三分，釉不挂泪”，正对上单子上那句“盛汤不裂”，银子便分到了城西。老总管跑到半街就折回来的事，再不会有了。

可新规矩行了半月，又出了岔子。一个采买只懂一行：管药材的看不准绸缎的成色，管绸缎的分不清南货的新陈。八样货，他一个人只有一张单子，单子上再多写几句，也问不到点子上。

少爷便派了八个采买，一人管一行：药材、绸缎、瓷器、南货、铁器、纸张、香料、牲口。八个人各持各的单子，走的是同一条街；只是单子上的问法不同——管药材的问药性，管绸缎的问成色，管瓷器的问火候。

八个人回来，把八包货并作一包，账房再按总账核一遍——哪一行的份额重了，哪一行的轻了，都在合账时调匀。

又过了些日子，少爷发现还有一处不对：摊子自己，也该有单子。

一摊该进什么货、该出什么价，不能只看自家门前的三尺地。绸缎摊得看街尾的染坊今年出不出新色，药材摊得看码头上的船几时到。于是每个摊子也派一个伙计，拿着本摊的单子，去逛别家的招子。三百个摊子，家家既是卖家，也是买家。

街是有次序的。摊子按门牌一号一号排下去，采买的单子上也写明“我是从几号摊来的”。不写这一笔，一条街上前后不分，头尾一乱，谁先摆的货、谁后补的货就说不清了。

还有一条铁规矩：走到几号摊，就只能看几号以前的招子。后面的摊子布还盖着，货还没摆出来，谁也不许掀。掀了，就等于拿明天的行情做今天的买卖。

分银子也有讲究。单子写得长、招子写得满，两两对下来，数目就大；数目一大，一家摊子能把一日的银子独吞了去。所以新规里添了一笔：先把对出来的数目按“条目多少”开方折算，再分银子。这样，单子再长，也不至于只听一家的。

日子一长，长街还是那条长街，庙会还是那个庙会。只是街口的石碑上多了一行字：货不问人，牌不问名。

有外乡来的客商不懂，问沈家少爷：从前一个总管也办了二十年，何苦费这些事？

少爷指着满街的招子：

“从前一条街只有一个采买，他的眼睛就是整条街的秤。

如今这条街上，每一张单子都在问每一块招子——

谁该听谁的，不由人说，由货说。”

谜底

注意力机制

Attention · Transformer

这个故事讲的是 Transformer 里的注意力机制（attention）。一句话进来，先被切成一个个 token；每个 token 都生成三样东西：一个 Query（我在找什么）、一个 Key（我能提供什么）、一个 Value（我真正携带的内容）。每个 Query 与所有 Key 逐一比对，算出分数，经 softmax 变成一组和为 1 的权重；再按这些权重把各处的 Value 加权求和，就得到这个位置的新表示。Transformer 能处理长距离的依赖，靠的就是这一步：任意两个位置之间只隔一次比对，不必像循环网络那样一站一站地传。

一句话里，每个字都在问所有字

把一句话喂进 Transformer，第一步是切成 token——可能是字、词或子词。此后每一层里，每个 token 都会向序列中所有 token（包括自己）发问：你和我有多大关系？得到的回答是一组权重，权重大的位置，其内容就更多地混进当前 token 的表示里。这就是自注意力（self-attention）。故事里“家家既是卖家，也是买家”，说的正是这一点：没有谁只被动地等着被查，每个位置都同时发出 Query、挂出 Key、备着 Value。也正因如此，注意力本身并不在乎词序——把一句话打乱，两两比对的结果还是一样，所以必须另外把位置信息加进去。

单子、招子、货：Q、K、V 从哪来

Query、Key、Value 并不是原文的三份拷贝，而是同一个 token 表示经过三个不同的可学习线性变换得到的：Q = XW_Q、K = XW_K、V = XW_V。三者的分工不同：Query 是“我要找什么”，Key 是“我能应什么”，Value 是“我实际交出的内容”。之所以要分开，是因为“被找到”和“被取走”本可以是两件事——一块招子可以写得很响，摊上的货却未必对路。跨语言翻译、图文对齐里的交叉注意力（cross-attention）也是同一套动作，只是 Query 来自解码器，Key 与 Value 来自编码器：拿自己的单子，去查别人的招子。

为什么要先开方折算：缩放点积与 softmax

打分用的是点积：score = Q·Kᵀ。维度 d_k 越大，点积的方差越大，分数之间拉得越开；直接送进 softmax，最大的一项会接近 1，其余接近 0，梯度也随之消失。所以要先除以 √d_k，把分数拉回一个温和的范围——故事里“按条目多少开方折算”，就是这一笔。softmax 再把一行分数变成概率：α = softmax(QKᵀ/√d_k)，每一项非负，一行加起来恰好为 1。这和“一日的银子总数定死、按对得上的程度分完”是同一个意思：注意力不是在每一处都取满分，而是在有限的总量里做分配。温度、top-k、稀疏注意力，改的都是这场分配的规矩。

八个采买：多头不是把同一个问题问八遍

一个注意力头只能学出一种“怎么算相关”。语言里的相关却有很多种：主谓谁配谁、代词指向谁、修饰语管到哪、语气前后怎么呼应。多头注意力（multi-head attention）让 h 组不同的 W_Q、W_K、W_V 并行工作，每组把表示投到更低维的子空间里各比各的；最后把 h 个输出拼起来，再乘一个 W_O 合账。故事里八个采买看的是同一条街，只是各自带着不同的问法——这正是“同一条街、不同子空间”的意思，而不是把长街切成八段各管一截。实践中有个头专门盯句法，有个头专门盯指代，也有许多头的作用至今说不清；头数与每头维度通常此消彼长，总计算量大致不变。

门牌、遮着的布与账本：位置、遮罩和代价

注意力对顺序无感，位置编码（positional encoding）负责把“第几号摊”补回去：早期用正弦函数或可学习向量直接加在词嵌入上，如今大模型多用旋转位置编码（RoPE），把位置信息转进 Query 与 Key 的夹角里。解码器生成时还要加因果遮罩（causal mask）：把未来位置的分数置为负无穷，softmax 之后权重自然为零——故事里“后面的布不许掀”，就是不许偷看还没生成的词。代价是两两比对：序列长 n，分数矩阵有 n² 个格子，时间和显存都随 n² 增长；于是有了 FlashAttention 这类把计算分块、减少显存读写的工程做法。自回归逐字生成时，前面算过的 Key 与 Value 可以存下来复用，这就是 KV 缓存——摊子的招子与备货记在簿上，下一回不必重问。也别忘了每个注意力子层外面的残差连接与层归一化：新采买的货并到旧账上再记一笔，账才不至于越写越偏。

注意力不是全部，也不一定是解释

一层 Transformer 里，注意力只负责“把别处的内容混进来”；混完之后，每个位置还要过一个逐位置的前馈网络（FFN），那才是真正做变换、做记忆的地方。残差连接让信息有一条不过注意力的直路，层归一化稳住数值。另一个常见的误会是拿注意力权重当解释：某几个词权重大，不代表模型就是靠它们下的判断。权重只说明这一层、这一头在这一步混入了多少，经过多层多头、残差与 FFN 之后，最初的分配早已被反复改写。故事里那本分银子的账簿，能说明当时比过哪些招子，却不足以说明最后为什么买了这一包货。注意力是 Transformer 的入口，不是它的全部。
