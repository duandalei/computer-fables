按名索址

—— 一个关于“记得名字，不记得门牌”的故事

临河镇的人，记字号不记门牌。“同福客栈”“成记米铺”“李家染坊”，一说都知道；可要问门牌，十个人里有八个答不上来。信局立了门牌之后，信差好办了，寄信的人还是犯难：写信封的时候，总不能在“收信人”旁边写一串自己都不记得的号。

信局便在门口设了一个“问名处”。谁要寄信，先到问名处报字号；问名处的先生翻一本厚册，查出对应的门牌，写在纸条上，收两个铜钱。起初全镇只有这一本册子，先生坐在柜台后，从早翻到晚；册子越订越厚，翻一页要半天，问的人排到街上。

有一年，册子还出了错：一家客栈搬了家，册子上还是旧门牌；信按旧门牌送去，新住户说没这个人，信又退回来。掌柜的去问名处理论，先生说：我这册子是一个月前抄的，抄的时候他还在旧地方。掌柜的说：那你这册子，还不如我问路。

老驿丞听说了，把问名处改了。

他把一本厚册拆成几本。最上面一本是“总册”，只记大类：米铺归粮行公会，客栈归旅业公会，染坊归染业公会；总册不记哪一家，只记“这类字号，去问哪个公会”。公会里再有一本册子，记着本行各家的门牌；各家自己报，搬了家自己来改。信局另设几个“问事处”，替寄信的人跑腿：先翻总册，找到公会；再问公会，找到那一家；最后问那一家自己，确认门牌。

这样一来，谁也不必记全城。总册只记“去哪儿问”，公会只记“本行有哪几家”，店家只记“自己在哪儿”。一本册子管一段，段段相接，问到底，便是门牌。

问事处也不是白跑。每问成一桩，先生就在自己的小本上记一笔：某字号，某门牌，某日问的。下回再有人问同一家，先翻小本；小本上有，就不必再跑。小本上还注着日子：过了三日，这一笔就作废，得重新问。为什么？因为店家会搬家，门牌会换人；小本记的是“某日的门牌”，不是“永远的门牌”。

小本一多，又出了新麻烦。

有的先生图省事，小本上的日子过了也不去重问，照着旧门牌给人指路；信送到旧地方，自然找不到人。还有更坏的：有人在问事处门口摆一张桌子，冒充先生，专把“同福客栈”的门牌写成自己家；寄信的人不辨真假，信就落到了他手里。镇上管这个叫“换名”。

老驿丞立了两条规矩。一条是“问名处只报门牌，不代送信”：先生把门牌写在纸条上，盖一个问名处的戳，寄信的人自己封、自己递；先生不碰信，也不碰信里的银子。另一条是“新问的名，要跟旧名对得上”：若一家字号报上来的门牌，跟公会册子上的对不上，先生得再问一遍；若公会册子跟店家自己说的也对不上，就以店家自己说的为准，但要在册子上注明“某日改”。

后来镇上又来了一个懂洋文的先生，说洋人的问名处还要“验印”：总册、公会册、店家自己的册子，层层都有印，印对不上，问出来的门牌就不作数。老驿丞听了，说：这跟我们的戳是一个道理。名字可以冒，印不能冒；门牌可以搬，印不能搬。

问名处越办越顺。寄信的人到了门口，报一声“同福客栈”，先生翻总册、问公会、对店家，三步走完，一张纸条递出来：东字十七号。寄信的人拿着纸条，照门牌写信封，信差便不再问路。

也有问不着的。有的字号刚开张，公会还没登记；有的字号关了门，册子上还挂着。先生便在纸条上写“查无此号”，让寄信的人回去问清楚再来。老驿丞说：问不着也是话，总比让人拿着信在街上乱转强。

有人问老驿丞：既然门牌这么要紧，为什么不干脆让每家把门牌写在招牌上？老驿丞说：招牌是给客人看的，门牌是给信差看的；客人记字号，信差认门牌。问名处做的，就是把客人嘴里的字号，换成信差脚下的门牌。

镇口石碑上又添了一行：名可问，址可查。

域名系统

Domain Name System

这个故事讲的是 DNS（Domain Name System，域名系统）：把人类记得住的名字，换成机器能用的 IP 地址。www.example.com 是名字，93.184.216.34 是地址；DNS 就是那个“问名处”。它是一套分布式的层次数据库，不是一个中央服务器：根域在最上面，下面是顶级域（.com、.cn、.org），再往下是二级域名、子域名；每一层由不同的机构维护，谁家的名字谁家自己报。

要把 DNS 和另外两件事分开：DNS 只负责“名字 → 地址”，不负责把数据送到；地址到了之后，路由负责找路，TCP 负责可靠传输。DNS 也不等于“网站目录”，它解析的是任何域名，邮件、API、CDN、验证记录都用它。

名字为什么需要一套系统

IP 地址是给机器用的，人记不住，也不该记：服务器换机房、换云、换 CDN，地址都会变。域名是给人用的稳定名字，DNS 负责把名字翻译成当下的地址。翻译必须分布式：全世界有数亿个域名，没有任何一台机器能存下并实时更新全部记录，也没有任何一家机构愿意为所有名字的准确性负责。于是 DNS 按层次切分：根域只管“顶级域在哪里”，顶级域只管“这个二级域委托给谁”，每个域的权威服务器只管自己那一区的记录。每一层只做一小段，合起来就是全球目录。这种“委托 + 缓存”的结构，和故事里总册、公会册、店家册的分法一样：谁也不必知道全城，只要知道下一步问谁。

域名的层次与委托

一个完整域名从右往左读：最右边是根（通常省略，写作一个点），然后是顶级域（com、cn、org、io），再往左是二级域（example.com），再往左是子域（www.example.com、api.example.com）。每一级都可以把下一级“委托”出去：.com 的服务器不保存 example.com 的具体记录，只告诉你去问 example.com 的权威服务器。域名注册商负责登记二级域，并把它的 NS 记录写进顶级域；域名持有者再在自己的 DNS 服务商那里配置 A、AAAA、CNAME、MX 等记录。一个“区”（zone）是某个域及其委托出去的子域之外的部分；区文件里的 SOA 记录写明这个区的主服务器、管理员邮箱、序列号与各种超时。理解“委托”二字，就理解了 DNS 为什么能无限扩展：加一个新域名，不需要通知全世界，只需要在自己的上级那里挂一条 NS。

一次解析怎么走

浏览器要访问 www.example.com，先问操作系统：本地缓存里有吗？hosts 文件里有吗？没有，就发给配置的递归解析器（通常是运营商或公共 DNS，如 1.1.1.1、8.8.8.8）。递归解析器如果也没有缓存，就从根服务器开始迭代：根说“.com 去问这些服务器”；解析器问 .com，.com 说“example.com 去问它的权威服务器”；解析器再问权威服务器，拿到 A 记录，返回给客户端，并按 TTL 缓存。整个过程对客户端是递归的——我只问一次，你负责跑完；对解析器是迭代的——每一台服务器只给下一步的地址。缓存存在于每一层：浏览器、操作系统、解析器，甚至权威服务器前面的缓存。TTL 是缓存与新鲜的折中：TTL 长，解析快、权威服务器压力小，但改记录后要等更久才生效；TTL 短，切换灵活，但查询多。否定结果（NXDOMAIN）也会被缓存，避免反复查询不存在的名字。

记录类型：不只是“名字 → IP”

最常见的是 A（IPv4 地址）与 AAAA（IPv6 地址）。CNAME 把一个域名别名到另一个域名，适合“www 指向主站”这类场景，但 CNAME 不能与同名的其他记录共存，也不能用在根域上。MX 指定邮件服务器，带优先级；TXT 常用来做域名验证、SPF、DKIM、DMARC；NS 指定这个区的权威服务器；SOA 描述区的基本信息；SRV 指定某服务的 host 与 port；PTR 做反向解析（IP → 名字），常用于邮件服务器的信誉检查；CAA 限制哪些证书机构可以为这个域签发证书。一个域名可以有多条 A/AAAA 记录，客户端通常按顺序尝试或轮询，这就是最朴素的 DNS 负载均衡；CDN 与云厂商还会根据用户位置、健康检查返回不同的地址（地理 DNS、anycast）。DNS 记录是公开的，任何人用 dig、nslookup 都能查——所以不要把秘密写进 TXT。

缓存、失效与安全

DNS 的安全问题主要有两类：一是“看到你在查什么”，二是“给你一个假答案”。明文 DNS 查询（UDP 53）可以被路径上的设备窥探，也可以被伪造响应；缓存投毒则把假记录塞进解析器的缓存，让一大片用户被引到错误地址。DNSSEC 用数字签名给记录做“验印”：解析器可以验证答案确实来自这个区的权威服务器，且没有被改过。但 DNSSEC 只保证“答案是真的”，不保证“查询是私密的”；DoT（DNS over TLS）与 DoH（DNS over HTTPS）把查询加密，解决隐私问题，却也让网络管理员更难看到内部解析流量，带来新的治理争议。还有“换名”式攻击：攻击者控制一个域名，把它解析到自己控制的地址，再配合证书申请，做出一个看起来很像的站点；这要靠证书透明度、HSTS、CAA 等多层防线。DNS 本身不是安全边界，它只是一个分布式数据库；安全要在它上面和旁边另做。

DNS 不做什么

DNS 不转发你的网页请求，不建立 TCP 连接，不保证你连上的服务器就是你想找的那台——它只把名字翻译成地址。DNS 也不等于“负载均衡器”：多条 A 记录只是给出候选地址，客户端怎么选、失败怎么重试，由客户端和网络库决定；真正的负载均衡通常在反向代理、四层/七层负载均衡器或 CDN 边缘做。DNS 的缓存和 TTL 让“改地址”不是瞬时生效的，做迁移时要提前调低 TTL，再切换，再调回。最后，DNS 查询本身也要走网络：它可能走 UDP，也可能因为响应太大或需要可靠性而改用 TCP；它也会被防火墙、NAT、运营商劫持影响。理解这些边界，才不会把“DNS 配好了”当成“网站就能访问了”——从名字到页面，中间还有路由、TCP、TLS、HTTP 好几道关。
