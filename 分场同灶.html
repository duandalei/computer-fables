分场同灶

—— 一个关于“什么该分、什么该共”的故事

徽州府城西的程家酱园，晒场上摆着一百二十口酱缸。缸是祖上传下来的，一口一号，号刻在缸沿上。每年入了伏，日头一上来，缸里的酱就要有人翻；翻过一遍，在缸册上记一笔——几日几时，谁翻的，晒到几分干。

早年间，园里只有一座院、一道门、一串钥匙、一本缸册。院门一关，账房、库房、曲房、晒场，全锁在里头。管事的是程家的老舅公，带着七八个伙计。哪一缸几时下的豆、几时磨的酱、晒到哪一日该出，全凭老舅公一个人记。伙计们手脚也利索，一百二十口缸，一年下来不曾误过一缸。

可园子一大，事就杂了。

有一年五月，一个伙计夜里贪凉，把油灯搁在曲房的木架上，打翻了。火从曲房烧到库房，又蔓上晒场，一百二十缸酱，一缸没剩。第二年又出一桩：一个伙计把没晒透的一缸酱当了成品，装坛卖到邻县，吃倒了人。官府来查，封条一贴，整座园子封了三个月。

东家算了三夜账，算明白一件事：园子里的祸，从来不是一个人的祸。一个人打翻灯，全园一起烧；一个人记错数，全园一起封。伙计再多，也是同一条船——船翻了，谁也游不上岸。

东家把园子分了。

城西老场留着晒酱，城东置了一处新场，码头边赁了一间仓场。三处各有各的围墙，各有各的门，各有各的一串钥匙，各有各的一本缸册。城西的缸只记城西的号，城东的账不进城西的柜。

三处场之间，伙计不串门，钥匙不外借。城东场半夜塌了半间库房，城西场的人第二天早上才听说；听说的时候，城西的酱正晒到第三遍。码头仓场叫官差封了，城西、城东照常开园。

要调货，走正道。城西要城东的十坛豆瓣，须写一张调货单，盖上本场的戳，从门房递出去；城东收了单，回一张收单。翻墙进库房是不许的——翻了墙，两本账就再也对不上。

可城西老场的活儿还是重。七十口缸，五六个伙计，日出翻到日落，还是赶不上日头。

东家原想再开一处场，把缸分出去一半。到晒场上一看，又作罢了：晒场就那么大，缸就是那些缸，再开一处场，也晒不出多一寸的日头。况且新开一处，要置地、砌墙、配钥匙、立账册、请门房，一摊子开销，够雇十个伙计。

东家便改了主意：场不新开，人往里添。

城西老场添了五个伙计。五个人同在一座院里干活，共用一座晒场、一间库房、一串钥匙、一本缸册。缸册搁在晒场边的木架上，谁翻完缸，谁就去记一笔。

可每人手里，另有一本自己的手记。手记上写的各不相同：张三写“翻到第十七缸，手里还剩三铲盐”；李四写“曲房第二架，明日出曲”；王五写“码头来船，午后卸豆”。各人的手记各人拿，别人不翻——翻了也没用，那上头记的是他手底下这一摊子活儿。

东家说，这就像一户人家添了双筷子：不用另起炉灶，不用另配门锁，添一张桌、一副碗筷，就能上桌吃饭。

同灶吃饭，吃得快，也容易碰着胳膊肘。

头一桩出在缸册上。有一日，张三和李四同时翻到第三十缸。张三提笔写“三月初七，翻第三十缸，晒七分”；李四也提笔，写“三月初七，第三十缸下盐二斤”。两支笔落在同一页上，墨迹压成一团。到了秋天核账，谁也说不清那缸酱晒了几分、下了几斤盐。那缸酱，只好倒了。

老舅公想了个法子：在缸册上挂一块木牌，牌上刻一个“记”字。谁要动笔，先取牌；取不到牌的，就在旁边等着，或者先去干别的活儿；写完，把牌挂回原处。木牌只有一块，从此缸册上再没压过墨。

库房没到货时，伙计也不守在门口空等：把钥匙挂回原处，回晒场翻缸；船一到，门房在院里喊一声，听见的再回来取货。

也有等不及的。一个伙计嫌牌子老在别人手里，索性不取牌，硬往册上写。那一页写废了，重抄了三天。

第二桩出在钥匙上。库房有两把钥匙，一把铜的，一把铁的，规矩是开库时两把一起取、一起用。有一晚，甲取了铜钥匙，乙取了铁钥匙，两个人都要进库房。甲说，你先把铁的给我；乙说，你先把铜的给我。谁也不肯先松手。两个人在库房门口站了一夜，天亮时东家来了，才看见两人手里各攥着一把钥匙，谁也没进成库房。

还有一桩，东家起初没想明白。

同院的伙计，添了人，也添了牵连。有天夜里，一个新来的伙计打翻了油灯，火从曲房烧起来。这一回，火只烧了城西老场——城东新场隔着两条街，第二天照常翻缸；码头仓场只闻到一点烟味。

可城西老场里，十几个伙计、七十口缸、一本缸册，一起烧了。东家站在废墟上，接过城东送来的账册，才明白过来：分场分的是祸，不是把祸分小了；是让这一处的祸，烧不到别处去。可一处院里的人，还是同生共死。

后来东家又添了一样东西：一只沙漏。

院里人多，活儿杂。东家请了一位执事，守着沙漏在晒场上看着。翻缸的翻一阵，去曲房帮一阵，再去库房点一阵。沙漏漏完，换一个人；换人的时候，伙计先在自己的手记上记下“翻到第几缸、手里几铲盐”，换回来时看一眼手记，接着往下干。手记不记，换回来就接不上了。

换人容易，换场难。城西的伙计去城东帮一天忙，得把钥匙、缸册、手记全交割清楚，连门房的登记都要重写一遍。所以东家轻易不换场，只在一处院里换人。

一个院里，几双手可以同时翻几口缸；一个执事，却只能挨个儿照看几摊活儿。人手多了，日头还是那一个日头。

日子一长，程家的酱卖到了邻府。三处场，各开各的门，各记各的账；一处院里的人，同用一本缸册，同晒一场日头。

有外乡客商来园里看，问东家：既是同一座园，何必分作三处场？既是三处场，何不各雇各的人，各烧各的灶？

东家领他到晒场上，指着满院翻缸的伙计：

“门要各开各的，一处封了，别处照常开张；

灶要同烧一口，一处的人，才不必为一碗饭来回递条子。

分的是门，共的是灶。”

园门口的石碑上，后来刻了一行字：门各开，灶同烧。

谜底

进程与线程

Process · Thread

这个故事讲的是操作系统里最容易被混为一谈的两个东西：进程（process）与线程（thread）。进程是程序的一次运行，带着自己的一整套资源——独立的虚拟地址空间、页表、打开的文件、信号处理、工作目录和一个 PID；线程是进程里的一条执行流，同一个进程的线程共享代码、全局数据、堆和打开的文件，各自只有一份栈、一组寄存器和程序计数器。一句话说：进程是资源分配的单位，线程是 CPU 调度的单位。故事里“场”与“伙计”的分法，分的正是这两件事。

程家酱园一分为三：城西老场、城东新场、码头仓场
一个程序可以跑成多个进程，各是独立的一次运行
每处场各有围墙、门、一串钥匙、一本缸册
每个进程有独立的虚拟地址空间与资源：页表、文件描述符、信号、工作目录
城东场半夜走水，城西场第二天照常翻缸
进程隔离：一个进程崩溃或被杀死，不连累其他进程
场与场不串门，调货开条子、递帖子、走门房
进程间通信（IPC）：管道、套接字、消息队列、共享内存
新开一场要置地、砌墙、配钥匙、立账、请门房
创建进程开销大：fork 复制页表（写时复制）、分配资源，exec 再换掉程序映像
东家在一座场里添了五个伙计
在一个进程里创建多个线程
五个伙计共用一座晒场、一间库房、一串钥匙、一本缸册
线程共享地址空间：代码段、全局数据、堆、打开的文件
每人另有一本自己的手记，记着翻到第几缸、手里几铲盐
每个线程有自己的栈、寄存器、程序计数器与线程局部存储
添一个伙计，不过添一张桌、一副碗筷
创建线程比创建进程轻：只需分配栈和线程控制块
换手看一眼手记就能接上；换场要交割钥匙账册、重新登记
线程切换不换页表，缓存仍热；进程切换要换地址空间、刷新 TLB
两个伙计同时往缸册同一页落笔，墨迹压成一团
竞态条件：共享数据的并发读写，结果取决于调度顺序
缸册上挂一块“记”字木牌，动笔先取牌，写完挂回
互斥锁（mutex）与临界区：同一时刻只许一个线程进入
库房没货时把钥匙挂回，回晒场干活；船到了，门房喊一声再回来
条件变量：等待某个条件成立时先释放锁，条件满足后被唤醒
有伙计不取牌硬写，写废一页
有一处访问漏了锁，共享数据就保不住；锁保护的是数据，不是代码
甲取铜钥匙、乙取铁钥匙，各等对方先松手
死锁：互斥、持有并等待、不可剥夺、循环等待
一场走水，同院伙计与缸册一起烧了；别场只闻到烟味
线程共享进程命运：一个线程崩溃常使整个进程退出；进程是故障的边界
东家原想多开场，可晒场就那么大，缸就那些缸
进程默认不共享地址空间；多开进程不等于多出算力，共享要靠显式 IPC
执事守沙漏，一漏换一个人；一个院里几双手同时翻缸
操作系统按时间片调度线程，切换时保存与恢复现场；多核上多线程真正同时执行

场分资源，人分工夫

程序是写在纸上的谱子，进程是照着谱子真正唱起来的一台戏。它有自己的地址空间、页表、打开的文件、信号处理、工作目录和一个 PID。操作系统把进程当作资源分配的容器；线程才是容器里真正干活的手。同一进程内的线程共享代码段、全局数据、堆和打开的文件，各自只有一份栈、一组寄存器和程序计数器，以及一份线程局部存储（TLS）。所以一个线程在堆上分出来的东西，另一个线程拿着指针就能用；而在两个进程之间，同样的地址往往指向完全不同的东西。故事里，场与场各有各的缸册，场里的伙计却同看一本。

为什么添人便宜，开场贵

新开一场，要置地砌墙，对应 fork 时复制页表、继承或新建各种资源；exec 还要把整个程序映像换掉。现代系统用写时复制（copy-on-write）让 fork 便宜了不少，但进程切换仍要换页表、刷新 TLB，缓存也要重新暖起来。添一个伙计，只需分配一块栈（通常是虚拟地址，用到才真正占内存）和一个线程控制块；线程切换在同一地址空间里进行，页表不动，缓存多半还热。不过便宜不等于免费：每个线程都有自己的栈，成千上万个线程会吃掉大量虚拟内存，调度与同步的开销也会上来。所以常见做法是开一个线程池，人不够时排队，而不是来一桩活儿就雇一个人。

同灶的代价：竞态与锁

两个伙计同时改同一页账，结果取决于谁先落笔——这就是竞态条件（race condition）：多个线程访问同一份共享数据，至少有一个在写，又没有同步。被争抢的那段代码叫临界区。木牌就是互斥锁（mutex）：进入临界区前加锁，出来解锁，同一时刻只放一个人进去。更底层的做法是原子操作，锁本身也常由它实现。锁保护的是数据，不是某一段代码——只要有一处访问没拿锁，木牌就白挂了。等牌的人可以空转，也可以被挂起、等别人写完再唤醒；后者通常配条件变量使用。读写锁让多个读者并行、写者独占；信号量则管“同时最多几个人”。锁的粒度也要拿捏：锁得太粗，大家排队；锁得太细，开销和死锁的风险都上来。锁还顺带规定了可见性：一个线程在锁里写下的东西，另一个线程拿到同一把锁后一定看得见。

两把钥匙：死锁

死锁要凑齐四个条件：互斥、持有并等待、不可剥夺、循环等待。故事里两把钥匙，四个条件一个不少。最实用的解法是给所有锁排一个全局顺序——规定必须先取铜钥匙、再取铁钥匙，循环就断了；其次是取不到就放回、退一步重来（trylock 加退避），或者给等待设一个上限。操作系统也能检测：把“谁在等谁”画成图，图里出现环就是死锁。还有两种没那么显眼的毛病：活锁是两个人同时松手、又同时伸手，谁也没进展；饥饿是某个人永远排不上队。锁不是越多越安全，也不是越少越省事，关键是让所有访问者守同一套顺序。

同院同命：崩溃与隔离

线程之间没有围墙。一个线程写野了指针，踩坏的可能正是另一个线程的栈；一个线程触发段错误或调用 abort，整个进程都会退出，同院的伙计一起遭殃。进程之间则有操作系统砌的墙：各自的页表把地址隔开，一个进程崩溃，别的进程照常运行。所以浏览器把每个站点放进单独的渲染进程，nginx 用多个 worker 进程各自处理连接，PostgreSQL 给每个连接开一个进程；MySQL 则用线程，图的是连接之间共享缓存、切换更轻。两种做法没有高下，只是把墙砌在哪里。要注意，进程的墙也不是绝对的：共享内存、mmap、ptrace 都能把两边打通，一旦打通，同步的责任又回到你手里。

沙漏之外：调度、并发与并行

操作系统调度的是线程，不是进程。调度器按时间片把 CPU 轮流交给就绪的线程，切换时保存寄存器、程序计数器与栈指针，再恢复下一个线程的现场——就是故事里换人前先在手记上记一笔。一个核上交替执行叫并发（concurrency），多个核上真正同时执行叫并行（parallelism）；同院的五双手若真有五个核，才是并行。线程也不一定都由内核管：用户态线程、绿色线程、协程在用户空间自己切换，开销小得多，但一次阻塞式系统调用就可能卡住整个进程；Go 的 goroutine、Python 的 async/await、Node.js 的事件循环，都是在“轻量并发”上做文章。CPython 还有一把全局解释器锁（GIL），同一时刻只允许一个线程执行 Python 字节码，所以 CPU 密集的活儿它更推荐多进程。怎么选，看三件事：活儿是算得多还是等得多，数据要不要共享，出错时能不能连累别人。算得多、要隔离，用进程；等得多、共享多，用线程或协程。真实系统往往两者并用——nginx 是多进程，每个进程里再跑一个事件循环。
