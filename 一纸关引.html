印

一纸关引

—— 一个关于“不查名册也敢放行”的故事

从前北边有座朔风关，是进京的最后一道关口。商队、驿马、赶考的举子，都得从这道关门下过。

旧例是查名册。每个过关的人自报姓名籍贯，守卒抄录下来，派快马连夜送进京城；京城户部的名册房里坐着三百个书吏，翻册、核对、画押，再把回文送回来。一来一回，少说七日。这七日里，商队在关外扎营，骆驼瘦了一圈，赶考的举子在关墙下急得直转。

名册房还出过事。有一年，一个改了名姓的江洋大盗排在队伍里，等回文送到，他早已过了关，在千里之外喝上了酒。老卒叹气：不是我们查得不仔细，是我们总比人慢七天。

新来的关防官姓陆。到任头一件事，他把“回京核对”的旧例废了。

他命各州府设一个签发司。要领关引的人，先到签发司当面验明正身，签发司再把几行字写在一张带暗纹的厚纸上：

姓名，籍贯，左颊有一颗痣，

往何处去，同行几人，几日之内必须出关。

写罢，掌印官取出一枚朱印，在纸末重重一按。印是照着京城颁下的母印刻的，各关墙下挂的也都是同一本印谱。印纹一半压在字上，一半压进纸的暗纹里。

守卒验关，只看三样：纸上的字有没有刮改，印纹与印谱对不对得上，末尾的日子过没过。三样都对，一挥手，放行。快的只一个照面，慢的也不过数到二十。再不必派快马，再不必等七日。

有老卒不放心：这印，不就是个花押？会刻章的，谁不能刻一枚？

陆大人把两张关引并排摆在桌上，一张是真的，一张是从私刻匠人处缴来的。真的那张，印压在“左颊有痣”四个字上，朱色渗进纸纹；假的那张，印是新刻的，纹路差了一毫，暗纹对不上。老卒凑近看了半晌，认了。

也有人动过改字的念头。把关引上“往青石镇”改成“往京城”，找个好手把纸面刮得干干净净，字迹足以乱真。可那一改，印就断了——朱印压在字上，字一动，印纹便裂开。守卒迎着日头一照，当场拿下。

陆大人后来在关墙上立了块碑，碑上刻着一句话：印在字上，字不可改。

关引不封口，也不装匣。过关的人把它别在衣襟上，一路同行的脚夫、店小二，谁都看得见上边写的是什么。

有个绸缎商想显摆，把关引写成了一篇大文章：祖上三代做过什么官，家中存着多少银，这趟进京要谈几笔大买卖。还没到关口，就被一伙人盯上了，夜里连人带银劫了个干净。他去报案，差役看了看那张关引，说：这些事，是你自己写在纸上，给全天下看的。

陆大人后来立下规矩：关引上只许写过关要用的那几行。与过关无关的，一个字也不许多写。

第二年开春，关前来了一队人，领头的身穿官服，递上一张关引。姓名写了，末尾却干干净净，没有印。他说：京里新下的规矩，熟人过关，不必验印。

守关的年轻卒子不敢拦，正要抬手，被老卒一把拽住。老卒把那张纸翻来覆去看了半天，说：

“没有印的关引，不管上边写着多大的官，一律当贼办。”

后来查明，那身官服是十两银子买来的，京里也从没有过这样的规矩。陆大人听说后，在碑上又加刻了一行：只认印，不认人，不认话。

关引末尾的日子，是签发的第七日。日子一到，纸自己作废，守卒当场把它投进关墙下的火盆。过期一日，也不放行。

可还是出过难处。有一回，签发司发出去的一批关引里，有一张给了个通敌的粮商。他人还没到关下，密报先到了。可他的关引是三天前签的，七日期未满，印是真的，字也没动，守卒看不出半点破绽。

陆大人连夜召集众人。有人说，把作废的名字抄成名录，挂在每个关口，守卒先查名录，再验关引。

陆大人摇头：名录越抄越长，不出半年，又是一本户部名册。

最后定下的法子，是把期限从七日缩到三日；一日之内签出的关引另用一色纸，出了事，最先烧那一色。天下的关口因此没有一本查不完的名册，只是有些人的关引，比别人短命些。

关引认纸，不认人。有人偷了别人的关引，大摇大摆过了关。陆大人便在引上添了“左颊有痣”一行，守卒验印，也验人。可相貌写得再细，也挡不住同胞兄弟、熟识的旧仆。存心冒用的人，关口终究拦不住——关口认的，还是那张纸。

多年后，老卒带徒弟守关。徒弟问：师父，咱们既没有名册，也等不来京城的回文，凭什么就敢放人过关？

老卒把一张关引迎光举起，印纹清清楚楚：

“凭这张纸自己说话。

纸上有名，有貌，有去处，有归期；末尾一枚印，把满纸的字都封在里头——改一个字，印就断了。

京城的名册在七百里外，这张纸却在他手里。

我们不必知道他是谁，只消知道：这纸是官府亲手发的，一个字也没被人动过。”

徒弟又问：那要是官府发错了人呢？

老卒把纸丢进火盆，看它一寸寸卷起来：

“所以它只活三日。”

谜底

JWT

JSON Web Token · 自包含的通行令牌

这个故事讲的是 Web 开发里最常用、也最容易被误解的一种令牌：JWT（JSON Web Token，JSON 网络令牌）。它要回答的正是陆大人的那个问题——服务器如何在不查名册的前提下，确认一张凭证是真的、没过期、没被人改过。故事里的三样东西：纸上的字、末尾的印、末尾的日子，分别对应 JWT 的载荷（claims）、签名（signature）与过期时间（exp）。

京城户部的名册，每过一关都得回京核对
服务端会话（Session）：会话数据存在服务器上，每次请求都要查一次
关引自带姓名、相貌、去处、归期
自包含（self-contained）的声明（claims）：身份信息就在令牌里，客户端随身携带
签发司当面验身，写字，盖章
认证服务器签发令牌：先认证身份，再由它签发
一张关引分三截：用的什么印、写了几行字、末尾一枚印
JWT 的三段结构：Header.Payload.Signature，以点分隔
朱印一半压在字上，一半压进纸纹
签名覆盖头部与载荷：改动任何一个字节，签名即失效
守卒拿印谱对印，不必回京
验签（verify）：用密钥或公钥本地校验，无需查数据库
私刻的印，纹路差一毫
签名不可伪造：不知道密钥，就签不出能通过校验的令牌
关引明写，沿途脚夫都看得见
Base64URL 只是编码，不是加密；载荷对任何人可读
没有印的关引，称“熟人不必验印”
alg:none 攻击：必须拒绝无签名的令牌，并固定允许的算法
末尾的日子，三日即焚
exp（过期时间）声明：签发方写死，服务端必须校验
作废名录越挂越长，又成了名册
吊销名单（denylist）：无状态令牌无法直接收回，只能靠名单或短有效期兜底
期限缩到三日，一日一色纸
短时效 access token、refresh token 换新，以及签名密钥轮换
关引只许写要看的几行
声明应精简：令牌随每次请求发送，越大越慢，也越容易泄露
偷了关引就能过关
令牌窃取（token theft）：靠 HTTPS、短时效与额外绑定降低损失
各州照母印共刻一枚印；后来改为京城独掌私印、各关只拿印谱
对称签名（HS256，共享密钥，人人可验也人人可造）与非对称签名（RS256/ES256，私钥签发、公钥验签）

一张令牌长什么样

JWT 就是一张电子关引，串起来只有一行，用两个点分成三截：
第一截是头部（Header），写明这是什么类型的令牌、用哪种算法签的；第二截是载荷（Payload），就是“关引上的那几行字”，每一行叫一个声明（claim）——sub 是谁，exp 何时过期，iat 何时签发，iss 谁签的，业务需要的角色、权限也可以放进去；第三截是签名（Signature），由前两截加上密钥算出来。三截都用 Base64URL 编码，中间以点相连。服务端拿到它，先验签，再读载荷，全程不必查库——这就是“无状态”。

签名不是加密——这是最常被误解的一处

Base64URL 不是密码，也不是加密，只是一套把字节写成可传输字符的编码。浏览器控制台、在线工具，随手就能把载荷解出来。签名只保证“这张纸没被人改过”，绝不保证“没人看得见”。所以密码、身份证号、银行卡号、内部权限细节，都不该放进载荷。故事里那位把家底写在关引上的绸缎商，就是把“看起来像密文”当成了“别人看不懂”。

无状态的代价：发出去的令牌，收不回来

Session 像名册：服务器存着，删掉一条就失效一条。JWT 像关引：签出去就在用户手里，服务器没有底册。想让某张令牌提前作废，只能维护一份黑名单（denylist）逐张核对，或者干脆让它短命——access token 只活十几分钟，过期后用 refresh token 换新的；出了大事就轮换签名密钥，让所有旧令牌一起失效。故事里“把七日期缩到三日、一日一色纸”，正是短时效与密钥轮换的雏形。换句话说，无状态换来了不必查库的速度，代价是“收回”变得昂贵。

三处最常见的塌方

其一，alg:none——把算法交给令牌自己声明，攻击者改掉头部、去掉签名就能过关，正是故事里那张空白关引；服务端必须写死允许的算法。其二，弱密钥——拿一句短口令当签名密钥，等于刻章匠人一猜就中。其三，只解码不验签——只读载荷便信以为真，等于守卒只看纸上写了什么，不看印。还有一处：过期时间只在客户端检查，等于把火盆交给过关的人自己点。

寓言之外：什么时候其实该用名册

JWT 适合服务之间传递身份、短期授权，以及单点登录后跨域携带身份。它不适合当作“会话”的默认答案：需要立刻踢人下线、需要频繁改动权限、需要知道谁此刻在线——这些还是名册（Session）更合适。故事里各州府共刻一枚印，一处印谱失窃，天下都能伪造，这对应 HS256 共享密钥的风险；今天的系统更多用非对称签名：京城独掌私钥，各关只拿公钥验印，验印的人再多，也造不出一张假关引。
